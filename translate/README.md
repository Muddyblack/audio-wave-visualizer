# Translations

One gettext catalog per language, `translate/<lang>.po`, translates everything
a user reads, on every platform. QML calls `I18n.i18n("…")`, or `I18n.i18np("%1
bar", "%1 bars", n)` for counts and `I18n.i18nc("context", "…")` to tell apart
two meanings of a word. Text stored as data and translated when it is drawn is
marked `noop("…")` in JS and `I18n.noop("…")` in QML.

- `Messages.sh` extracts the strings into `template.pot` and merges it into
  every `.po`. Run it after changing a string; the pre-commit hook does.
- Every host reads the `.po` at runtime (`package/contents/ui/text/I18n.qml`,
  parsed by `ui/studio/I18n.js`), so Settings → Comfort & power can switch the
  language without a restart.
- `build.sh` copies each `.po` into the package and compiles the `.mo` Plasma
  reads for the store description.

## Translating on Weblate

The easiest way to help: open the project on Weblate, pick a language and
translate in the browser. Weblate commits back through a pull request, and the
next release ships it. A language does not have to be finished to be useful:
untranslated strings simply show in English.

## Translating locally

```bash
make new-language CODE=de      # starts translate/de.po from the template
# edit translate/de.po (Poedit, Lokalize, or any text editor)
make translations              # re-extract and merge, keeps your work
make check-translations        # every catalog must compile
```

The language setting offers every catalog it finds, so nothing else needs
changing.

Placeholders are `%1`, `%2`, … and may be reordered. Lines starting with `#.`
in the catalog are notes for translators; add one in the source with a
`// TRANSLATORS: …` comment on the line before the string.

`complete-languages` lists the languages CI requires to stay 100% translated;
any other language may be partial and shows English for the rest.

## Setting up Weblate (maintainers, once)

Weblate is free for open-source projects at <https://hosted.weblate.org>
("Libre" plan). Repository side, nothing else is needed: this layout is what
Weblate expects.

1. Sign in with GitHub, create a project (name: *Plasma Audio Visualizer*,
   website: the GitHub repository) and apply for Libre hosting.
2. Add one component:
   - **Source code repository:**
     `https://github.com/Muddyblack/audio-wave-visualizer`, branch `main`;
     **Repository push URL:** the same, via the Weblate GitHub integration (it
     then opens pull requests instead of pushing).
   - **File format:** *gettext PO file*
   - **File mask:** `translate/*.po`
   - **Monolingual base language file:** *(empty)*, PO is bilingual.
   - **Template for new translations:** `translate/template.pot`
   - **Language filter:** `^[a-z]{2,3}(_[A-Z]{2})?$`
   - **Adding new translation:** *Create new language file*.
3. Add-ons: enable **"Update PO files to match POT (msgmerge)"** so a new string
   reaches every language. Leave **"Update POT file"** off: `Messages.sh`
   produces the template, and CI keeps it and the `.po` files in sync.
4. Under *Settings → Commit messages*, a short prefix like `i18n:` keeps the
   history readable.
5. Link the project in the README ("Help translate") once it is public.

`template.pot` is committed for Weblate and regenerated by `make translations`;
commit it together with the `.po` files.
